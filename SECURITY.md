# Security policy

## Reporting a vulnerability

Use [Report a vulnerability](https://github.com/SAMS0N1TE/lr2021-sdr/security/advisories/new) to send a private report to the repository maintainer. You can also find it under **Security > Advisories** on GitHub.

Do not put vulnerability details, exploit code or credentials in a public issue or pull request before the maintainer has had a chance to investigate.

Include:

- The affected commit or release, board and LR2021 ROM version.
- The component involved, such as the capture protocol, a file or capture parser, the upload path or the transmit commands.
- Reproduction steps and a small test case, if available.
- The impact and any access or equipment needed to trigger it.
- A suggested fix or workaround, if you have one.

Remove unrelated personal data and secrets from attachments. Use your own equipment and data, or equipment and data you have permission to test.

## Versions and fixes

Report issues found in any version. Investigation and fixes focus on the current `main` branch and the latest release. Older releases do not have a separate backport commitment. Include the exact revision so the maintainer can check whether the issue still exists.

This is a maintainer-run project with no guaranteed response or patch deadline. The private report provides a place to discuss reproduction, fixes and disclosure timing.

For ordinary build failures, capture problems and setup questions without a security impact, use the [issue templates](https://github.com/SAMS0N1TE/lr2021-sdr/issues/new/choose).
